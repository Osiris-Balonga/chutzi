# Contributing to Chutzi

## Delivery flow

Create working branches from `dev` and open a pull request back to `dev`:

- `feature/<topic>` for a user-facing capability;
- `fix/<topic>` for a correction;
- `chore/<topic>` for maintenance or tooling;
- `docs/<topic>`, `refactor/<topic>` and `test/<topic>` when appropriate.

`main` only receives pull requests from `dev`. Do not push directly to `dev` or `main`.

## Pull requests

Link the related issue, keep the change focused, run the relevant checks and describe how the user flow was verified. The CI validates the branch name and static project checks automatically.
